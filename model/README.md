# Локальный сервис модели

`POST /predict` принимает сырой контракт `MLRequest` из бэкенда, рассчитывает признаки внутри сервиса и применяет `catboost_all.cbm`. Бэкенд и фронтенд не получают промежуточные признаки. Модель возвращает прогноз отклонения от плана в секундах; цвет риска по этому числу определяет бэкенд.

Данные хакатона в `dataset/` и таблица ML-команды `model/tests/reference/test_features_353.csv` не включаются в Git. Их нужно получить отдельно; тест сопоставления признаков пропускается, если таблицы нет.

## Запуск

Из корня проекта в отдельном окне PowerShell:

```powershell
python -m pip install -r model/requirements.txt
python -m uvicorn model.app:app --port 8081
```

Проверка: <http://127.0.0.1:8081/health/ready>, Swagger: <http://127.0.0.1:8081/docs>. В другом окне PowerShell установите `$env:ML_SERVICE_URL = "http://127.0.0.1:8081"` и перезапустите бэкенд. `docker compose -f backend/compose.yaml up --build` запускает оба сервиса вместе.

## Восстановленные признаки

Источником проверки служит переданный ML-командой `test_features_353.csv`. По всем 353 строкам удалось воспроизвести 14 доступных в таблице входов модели с числовым расхождением не больше `1e-10`:

- Координаты цели берутся из `schedule.geom`, `time_to_target_s` — разница планового времени и `T`, `current_dev_s` — из прогнозной точки.
- `last_message_age_s` и `last_speed_kmh` берутся из **последнего пакета** с `event_time <= T`. Недостоверная GPS-позиция не исключает скорость из расчёта.
- Окна скоростей включают пакет ровно на границе `T-1`, `T-3` или `T-5` минут. Пустое 1-минутное окно даёт `NaN`. `speed_std_5m_kmh` — стандартное отклонение с делением на `N`, `speed_change_5m_kmh` — последняя скорость минус первая, `stopped_share_5m` — доля скоростей `<2 км/ч`.
- `valid_messages_5m` считает пакеты с `location_valid=true` за последние 5 минут. `distance_to_target_km` — гаверсинус с радиусом Земли `6371.0088 км`; расстояние отсутствует, когда у последнего пакета недостоверная или отсутствующая GPS-позиция.

В переданной таблице **нет** `time_sin` и `time_cos`, хотя они есть в сохранённой модели. По названиям и границам числовых разбиений модели они восстановлены как `sin/cos(2π · время суток / 86400 секунд)` для `T` по московскому времени. Это обоснованное восстановление, но точное совпадение с обучающим кодом для этих двух полей ML-команда должна подтвердить.

Модель обучена с `current_dev_s`, а в живом NDTP-потоке эта величина сейчас неизвестна. Поэтому сервис возвращает `status=insufficient_data` без `cur_dev_s`, пока ML-команда не предоставит проверенный режим работы с этим пропуском или источник текущего отклонения. Тот же статус возвращается при пустой истории или отсутствии измеренной скорости за 5 минут. Модель не оценивает вероятность задержки; `delay_probability` остаётся `null`.

Метрика MAE `48.84 с` на присланных 353 строках подтверждает техническую согласованность вычислений и модели. Это **не независимая оценка качества**: неизвестно, входили ли эти строки в обучение `catboost_all.cbm`.
