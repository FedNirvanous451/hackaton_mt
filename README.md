# Прогноз задержек городского транспорта

- [`backend/`](backend/README.md) — мой FastAPI-бэкенд: NDTP, расписание, подготовка входных агрегатов, вызов ML API и данные для фронтенда.
- [`ml_core/`](ml_core/README.md) — модель и API команды ML. Исходники этой папки при интеграции не изменялись.
- [`frontend/`](frontend/) — панель диспетчера с картой, прогнозами и предупреждениями. История читается последовательными шагами HTTP, живой поток приходит через WebSocket.

Перед первым запуском загрузите образ эмулятора из локального набора данных:

```powershell
docker load -i dataset/ndtp-telemetry-emulator.tar
docker compose up -d --build
```

Панель: <http://127.0.0.1:3000/>, Swagger бэкенда: <http://127.0.0.1:8000/docs>, ML API: <http://127.0.0.1:8081/docs>. Схемы OpenAPI сохранены в [`backend/openapi.json`](backend/openapi.json) и [`ml_core/openapi.json`](ml_core/openapi.json); после изменения маршрутов обновите их командой `python scripts/export_openapi.py`.

Панель автоматически запускает поток `validate/traffic.csv`. Переключатель «Источник» включает настоящий NDTP-эмулятор; кнопки управляют воспроизведением или отправкой пакетов. Исторический кадр содержит **все** пакеты за выбранный шаг (в том числе без GPS), а валидные координаты накапливаются в путях. Все точки остановок берутся из полного расписания сразу при выборе источника: для текущего `validate` это 847 разных мест. «Все ТС» возвращает обзор карты, выбор машины выделяет её путь. Индикатор показывает число обработанных пакетов из 105 945.

Панель сохраняет выбранный источник, позицию и паузу исторического потока, фильтры и положение карты. После обновления страницы она восстанавливает пройденные пути; после обрыва WebSocket подгружает пропущенные пакеты. Временная недоступность backend не меняет источник. Если эмулятор недоступен или более 15 секунд не выдаёт NDTP-пакеты при работающем соединении, панель переключается на историю с последней сохранённой позиции и продолжает воспроизведение.

В таблице «Плановая остановка» показывает адрес из расписания (или ID, если адреса нет), «Плановое прибытие» — время по расписанию, «Прогноз прибытия» — это плановое время плюс предсказанная задержка. Статус «Последний прогноз» означает, что целевая остановка уже прошла или свежей телеметрии нет, поэтому показан последний рассчитанный результат. Если следующая остановка ещё вне горизонта модели, план показывается сразу, а статус — «Ожидание ML».

В `validate` телеметрия есть для 30 ТС, а расписание — только для 13 из них. Для остальных 17 ТС карта и таблица сохраняют последнюю телеметрию, но расчёт времени прибытия невозможен без плановой остановки; статус «Нет расписания» обозначает именно этот случай.

Локальный `dataset/` используется для исторического режима и **исключён из Git**. При запуске Compose он монтируется в бэкенд только для чтения. Для текущего потока расписание и фактические прибытия передаются через API; подробности в [`backend/README.md`](backend/README.md). Прежний локальный `model/` и тестовая HTML-карта не используются.

Файл модели в `ml_core/models/` хранится через Git LFS (`.gitattributes`). Перед `git add` и клонированием проекта нужен установленный Git LFS.
