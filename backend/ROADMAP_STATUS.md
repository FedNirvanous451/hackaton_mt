# Состояние backend

- Реализованы отдельный FastAPI-сервис, NDTP-приёмник, HTTP-вызов неизменённого `ml_core` и Swagger/OpenAPI.
- Backend рассчитывает агрегаты, которые требует `/predict` команды ML. Промежуточные признаки не входят в ответы фронтенду.
- Локальный `dataset/` снова служит источником исторической телеметрии, расписания и точек прогноза; он игнорируется Git и монтируется в контейнер только для чтения.
- Регистрации `unit_id → tr_id` берутся из локального CSV, а для текущего потока их можно обновлять через API. Текущее расписание и фактические прибытия поступают через API.
- Исторический replay идёт с шагом 15 секунд и публикует те же JSON-срезы через WebSocket, что и поток NDTP. HTML-карты в бэкенде нет.
- Выдаются текущее отклонение от графика, скорость по GPS-сегменту и время простоя. Декодируется статус дверей из необязательной ячейки NDTP IRMA; когда источник её не предоставляет, значение `null`.
- Тесты проверяют формулы признаков, исторический replay и обмен с ML-контрактом. Compose поднимает оба сервиса.

Ограничение прототипа: состояние находится в памяти одного процесса. Текущее расписание после перезапуска надо передать снова. CSV не содержит состояния дверей, а стандартная автогенерация эмулятора не отправляет ячейку IRMA. Для горизонтального масштабирования понадобятся БД и общий транспорт событий.
